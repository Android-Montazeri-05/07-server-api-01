# جزوه جامع آموزشی: مبانی سرور، دیتابیس، وب‌سرویس (API) و فرمت JSON

---

### چرا اصلاً به سرور، دیتابیس و وب‌سرویس نیاز داریم؟

فرض کنید می‌خواهید یک اپلیکیشن موبایل برای نمایش اطلاعات ۲۵۰ فیلم برتر دنیا بسازید. اگر بخواهید تمام اطلاعات، عکس‌ها و خلاصه داستان این فیلم‌ها را داخل خودِ فایل نصبی اپلیکیشن قرار دهید، با سه مشکل بزرگ روبه‌رو می‌شوید:

1. **حجم وحشتناک اپلیکیشن:** برنامه شما به جای چند مگابایت، چندین گیگابایت حجم خواهد داشت و هیچ کاربری آن را دانلود نمی‌کند.
2. **اطلاعات قدیمی و ایستا:** هر بار که فیلم جدیدی اکران شود یا نمره IMDB یک فیلم تغییر کند، مجبورید یک نسخه جدید از اپلیکیشن بسازید و از همه کاربران بخواهید برنامه را آپدیت کنند.
3. **عدم اشتراک‌گذاری داده:** اگر فردا بخواهید نسخه وب‌سایت یا iOS همین برنامه را بسازید، باید تمام اطلاعات را دوباره از صفر وارد کنید.

**راه‌حل مهندسی چیست؟**
اطلاعات را در یک مکان مرکزی به نام **سرور (Server)** و داخل **دیتابیس (Database)** ذخیره می‌کنیم. اپلیکیشن موبایل هیچ اطلاعاتی در خود ندارد؛ فقط هر زمان که کاربر صفحه را باز کرد، از طریق یک واسط به نام **وب‌سرویس (API)** درخواست می‌فرستد و اطلاعات را در قالب یک بسته متنی سبک به نام **JSON** تحویل می‌گیرد.

#### تشبیه دنیای واقعی (سناریوی رستوران)

برای درک بهتر رابطه این مفاهیم، یک رستوران را تصور کنید:

| مفهوم فنی | معادل در رستوران | وظیفه اصلی |
| --- | --- | --- |
| **اپلیکیشن (Client)** | مشتری نشسته سر میز | درخواست اطلاعات می‌کند و نتیجه را نمایش می‌دهد. |
| **دیتابیس (Database)** | انبار و یخچال مواد اولیه | محل نگهداری منظم و دائمی داده‌ها. |
| **سرور (Server)** | آشپزخانه | درخواست را پردازش می‌کند، داده را از دیتابیس می‌گیرد و آماده می‌کند. |
| **وب‌سرویس (API)** | گارسون | پیام مشتری را به آشپزخانه می‌برد و خروجی را برمی‌گرداند. |
| **فرمت JSON** | ظرف غذای استاندارد | بسته‌بندی استاندارد و سبک برای انتقال داده بین سرور و اپلیکیشن. |

---

### دیتابیس (Database) و سرور (Server) به زبان ساده

#### دیتابیس (پایگاه داده) چیست؟

دیتابیس نرم‌افزاری است که وظیفه ذخیره، جستجو و مدیریت حجم عظیمی از اطلاعات را به صورت کاملاً ساختاریافته بر عهده دارد. دیتابیس را می‌توانید شبیه یک **فایل اکسل بسیار پیشرفته و پرسرعت** تصور کنید که از جدول‌ها (Tables)، سطرها (رکوردها) و ستون‌ها (فیلدها) تشکیل شده است.

**مثال جدولی از دیتابیس فیلم‌ها:**

| id | title | year | imdb_rating |
| --- | --- | --- | --- |
| 1 | The Shawshank Redemption | 1994 | 9.3 |
| 2 | The Godfather | 1972 | 9.2 |
| 3 | The Dark Knight | 2008 | 9.0 |

#### سرور (Server) چیست؟

سرور در اصل یک **کامپیوتر واقعی** است (دارای CPU، رم و هارد دیسک)، اما با سه تفاوت مهم نسبت به لپ‌تاپ یا کامپیوتر خانگی شما:

* **۲۴ ساعته روشن است:** هیچ‌وقت خاموش نمی‌شود تا کاربران در هر ساعت از شبانه‌روز به آن دسترسی داشته باشند.
* **اینترنت پرسرعت و IP ثابت دارد:** آدرس مشخصی در اینترنت دارد تا اپلیکیشن‌ها همیشه بتوانند آن را پیدا کنند.
* **ظاهر گرافیکی ندارد:** معمولاً سیستم‌عامل لینوکس روی آن نصب است و برنامه‌نویسان از طریق خط فرمان (Terminal) آن را مدیریت می‌کنند.

---

### وب‌سرویس (Web Service) و API چیست؟

**API** مخفف عبارت *Application Programming Interface* (رابط برنامه‌نویسی کاربردی) است. وقتی یک API از طریق بستر اینترنت و پروتکل وب (HTTP/HTTPS) در دسترس قرار می‌گیرد، به آن **وب‌سرویس** می‌گوییم.

به زبان ساده برای برنامه‌نویس موبایل:
**وب‌سرویس یعنی یک آدرس اینترنتی (URL) که به جای نمایش یک صفحه رنگی و گرافیکی برای انسان، فقط «داده خام» را برای نرم‌افزار برمی‌گرداند.**

#### مفاهیم کلیدی در کار با وب‌سرویس:

1. **Endpoint (نقطه پایانی):** به هر آدرس اینترنتی مشخص در وب‌سرویس که کار خاصی انجام می‌دهد، یک Endpoint می‌گویند (مثلاً آدرس دریافت لیست فیلم‌ها یک Endpoint است و آدرس دریافت لیست ژانرها یک Endpoint دیگر).
2. **متدهای درخواست (HTTP Methods):** وقتی اپلیکیشن به سرور پیام می‌دهد، باید نوع درخواستش را مشخص کند:
* **GET:** دریافت اطلاعات از سرور (پرکاربردترین متد؛ مثل گرفتن لیست فیلم‌ها).
* **POST:** ارسال اطلاعات جدید به سرور (مثل ثبت‌نام کاربر یا ثبت نظر).
* **PUT / PATCH:** ویرایش اطلاعات موجود در سرور.
* **DELETE:** حذف اطلاعات از سرور.


3. **کدهای وضعیت (Status Codes):** سرور همراه با پاسخ، یک عدد سه‌رقمی می‌فرستد تا نتیجه درخواست را اعلام کند:
* **200 (OK):** همه‌چیز درست انجام شد و اطلاعات ارسال گردید.
* **404 (Not Found):** آدرس یا اطلاعات مورد نظر پیدا نشد (مثلاً فیلمی با شناسه ۹۹۹۹ وجود ندارد).
* **500 (Internal Server Error):** سرور دچار مشکل یا خطای داخلی شده است.

### فرمت JSON چیست و چطور خوانده می‌شود؟

**JSON** (مخفف *JavaScript Object Notation*) محبوب‌ترین فرمت متنی برای جابه‌جایی اطلاعات در وب‌سرویس‌هاست. دلیل محبوبیت آن **سبک بودن** و **خوانایی بالا** هم برای انسان و هم برای تمام زبان‌های برنامه‌نویسی (کاتلین، پایتون، جاوااسکریپت و...) است.

#### قوانین طلایی ساختار JSON:

1. **کلید و مقدار (Key-Value):** تمام داده‌ها به صورت جفت‌های `"کلید": مقدار` نوشته می‌شوند. کلیدها همیشه داخل دابل کوتیشن `" "` قرار می‌گیرند.
2. **آبجکت یا شیء (`{ }`):** هر موجودیت مستقل (مثلاً اطلاعات یک فیلم یا یک کاربر) داخل آکولاد باز و بسته `{ }` قرار می‌گیرد.
3. **آرایه یا لیست (`[ ]`):** مجموعه‌ای از چند آیتم (مثلاً لیست چندین فیلم یا لیست ژانرهای یک فیلم) داخل براکت باز و بسته `[ ]` قرار می‌گیرد.
4. **انواع داده در JSON:**
* **رشته متنی (String):** داخل کوتیشن، مثل `"The Godfather"`
* **عدد (Number):** بدون کوتیشن، مثل `1972` یا `9.2`
* **بولین (Boolean):** مقدار منطقی `true` یا `false`



**یک مثال ساده از JSON برای یک دانشجو:**

```json
{
  "student_id": 4021234,
  "full_name": "علی رضایی",
  "is_active": true,
  "courses": [
    "برنامه‌نویسی موبایل",
    "پایگاه داده",
    "سیستم‌عامل"
  ]
}

```

### مطالعه موردی و عملی با سایت `moviesapi.ir`

وب‌سایت **moviesapi.ir** یک وب‌سرویس رایگان و آماده است که اطلاعات ۲۵۰ فیلم برتر تاریخ سینما را بدون نیاز به ثبت‌نام در اختیار برنامه‌نویسان قرار می‌دهد. بیایید ساختار Endpointهای این سایت را بررسی کنیم:

#### ۱. دریافت لیست فیلم‌ها (Endpoint اول)

اگر آدرس زیر را در مرورگر خود وارد کنید، یک درخواست `GET` به سرور ارسال می‌شود:

```text
https://moviesapi.ir/api/v1/movies

```

**بخشی از خروجی JSON این آدرس:**

```json
{
  "data": [
    {
      "id": 1,
      "title": "The Shawshank Redemption",
      "poster": "https://moviesapi.ir/images/tt0111161_poster.jpg",
      "year": "1994",
      "country": "USA",
      "imdb_rating": "9.3",
      "genres": [
        "Crime",
        "Drama"
      ]
    },
    {
      "id": 2,
      "title": "The Godfather",
      "poster": "https://moviesapi.ir/images/tt0068646_poster.jpg",
      "year": "1972",
      "country": "USA",
      "imdb_rating": "9.2",
      "genres": [
        "Crime",
        "Drama"
      ]
    }
  ],
  "metadata": {
    "current_page": "1",
    "per_page": 10,
    "page_count": 25,
    "total_count": 250
  }
}

```

**تحلیل ساختار خروجی بالا:**

* کل پاسخ یک آبجکت بزرگ `{ }` است که از دو بخش اصلی تشکیل شده است:
* **`data`:** یک آرایه `[ ]` که در هر صفحه اطلاعات ۱۰ فیلم را نگهداری می‌کند. دقت کنید که تصویر پوستر فیلم (`poster`) به صورت مستقیم داخل JSON نیست، بلکه **لینک اینترنتی عکس** ارسال شده است تا اپلیکیشن آن را دانلود و نمایش دهد.
* **`metadata`:** اطلاعات راهنمای صفحه‌بندی (Pagination). به اپلیکیشن می‌گوید که در مجموع `250` فیلم وجود دارد که در `25` صفحه ۱۰تایی تقسیم شده‌اند و الان در صفحه `1` هستیم.



#### ۲. ارسال پارامتر در آدرس (Query Parameters)

برای اینکه به سرور شرط بدهیم (مثلاً صفحه دوم را بده یا فیلمی را جستجو کن)، از علامت سوال `?` در انتهای آدرس استفاده می‌کنیم:

* **دریافت صفحه دوم فیلم‌ها:**
```text
https://moviesapi.ir/api/v1/movies?page=2

```


* **جستجوی فیلم بر اساس نام (مثلاً جستجوی کلمه batman):**
```text
https://moviesapi.ir/api/v1/movies?q=batman

```



#### ۳. دریافت جزئیات کامل یک فیلم خاص (Path Parameters)

در لیست صفحه اصلی، خلاصه داستان (`plot`)، کارگردان (`director`) و بازیگران (`actors`) وجود ندارد تا حجم داده سبک بماند. وقتی کاربر روی یک فیلم کلیک می‌کند، اپلیکیشن شناسه (`id`) آن فیلم را به انتهای آدرس اضافه می‌کند تا اطلاعات کامل را بگیرد:

```text
https://moviesapi.ir/api/v1/movies/1

```

*(در این آدرس، عدد `1` شناسه فیلم رستگاری در شاوشنگ است).*

#### ۴. دریافت لیست دسته‌بندی‌ها و ژانرها

برای نمایش چیپ‌های دسته‌بندی (Action, Drama, Comedy و...) در بالای اپلیکیشن، از این آدرس استفاده می‌شود:

```text
https://moviesapi.ir/api/v1/genres

```

### تمرین‌های کلاسی و خانگی (همراه با پاسخ)

#### تمرین ۱: کشف داده از وب‌سرویس واقعی

آدرس `[https://moviesapi.ir/api/v1/movies/3](https://moviesapi.ir/api/v1/movies/3)` را در مرورگر خود باز کنید و به سوالات زیر پاسخ دهید:

1. نام این فیلم چیست و در چه سالی ساخته شده است؟
2. کارگردان فیلم کیست و نام کلید (Key) مربوط به کارگردان در JSON چیست؟
3. کلید `genres` از چه نوع داده‌ای (آبجکت یا آرایه) است؟

**پاسخ تمرین ۱:**

1. فیلم **The Dark Knight** محصول سال **2008**.
2. کارگردان **Christopher Nolan** است و در کلید `"director"` قرار دارد.


3. کلید `"genres"` از نوع **آرایه (Array)** است چون داخل براکت `[ ]` قرار گرفته و شامل چند رشته متنی (`"Action"`, `"Crime"`, `"Drama"`) است.

---

#### تمرین ۲: ساخت آدرس جستجو (Query Parameter)

می‌خواهیم در اپلیکیشن خود تمام فیلم‌هایی که در نام آن‌ها کلمه `lord` وجود دارد را از وب‌سرویس `moviesapi.ir` جستجو کنیم.

1. آدرس دقیق درخواست (Endpoint) را بنویسید.
2. با باز کردن این آدرس، چند فیلم پیدا می‌شود؟ (از بخش `metadata` پیدا کنید).

**پاسخ تمرین ۲:**

1. آدرس درخواست: `[https://moviesapi.ir/api/v1/movies?q=lord](https://moviesapi.ir/api/v1/movies?q=lord)`
2. با نگاه کردن به کلید `"total_count"` در بخش `"metadata"`، مشخص می‌شود که **۳ فیلم** با این عبارت پیدا شده است.

---

#### تمرین ۳: طراحی ساختار JSON (تفکر سمت سرور)

فرض کنید شما برنامه‌نویس سرور هستید و می‌خواهید اطلاعات یک **«محصول فروشگاهی»** را در قالب JSON برای اپلیکیشن موبایل بفرستید. این محصول باید شامل ویژگی‌های زیر باشد:

* شناسه محصول (عددی)
* نام محصول (متنی)
* قیمت به تومان (عددی)
* آیا موجود است؟ (بولین)
* لیست رنگ‌های موجود (آرایه‌ای از رشته‌ها)

یک نمونه معتبر از این JSON بنویسید.

**پاسخ تمرین ۳:**

```json
{
  "id": 104,
  "title": "هدفون بی‌سیم مدل X20",
  "price": 2450000,
  "is_available": true,
  "colors": [
    "مشکی",
    "سفید",
    "سرمه‌ای"
  ]
}

```

---

#### تمرین ۴: عیب‌یابی JSON (پیدا کردن خطاهای سینتکس)

قطعه کد JSON زیر دارای **۳ خطای نگارشی** است که باعث می‌شود اپلیکیشن موبایل هنگام خواندن آن کرش کند. خطاها را پیدا و اصلاح کنید:

```text
{
  id: 50,
  "course_name": "Android Programming,
  "students_count": 35,
  "topics": [
    "Kotlin",
    "Compose",
    "API",
  ]
}

```

**پاسخ تمرین ۴:**

1. کلید `id` بدون دابل کوتیشن نوشته شده است؛ باید به صورت `"id"` باشد.
2. مقدار `"Android Programming` در انتها با دابل کوتیشن بسته نشده است؛ باید به صورت `"Android Programming"` نوشته شود.
3. در انتهای آخرین عضو آرایه (`"API",`) یک ویرگول اضافی (Trailing Comma) قرار دارد که در استاندارد JSON غیرمجاز است و باید حذف شود.

**نسخه سالم و استاندارد:**

```json
{
  "id": 50,
  "course_name": "Android Programming",
  "students_count": 35,
  "topics": [
    "Kotlin",
    "Compose",
    "API"
  ]
}

```
